# 再接続AHK v4

AutoHotkey v2専用。v3は上書きしません。名前は継承していますが、v4は通信障害からの復旧専用です。定期的な移動・クリックなどのAFK操作、Falixの起動、広告や無料枠制限の回避は行いません。

## 初回設定（配信用PCで実施）

1. 旧AHKをF8またはタスクトレイから終了してください。別名のAHKは同時起動できるため、必ず旧版を終了します。
2. `anti_afk_simple_v4.ahk` を実行。初回メッセージを閉じます。
3. F5でゲームフォルダを選択します。対象は今回コピーしたレポートの置き場ではなく、配信中のMinecraftが書き込む `logs/latest.log` の親の親フォルダです。既定は `%AppData%\.minecraft`。
4. Minecraftの切断画面で「サーバーリストへ戻る」ボタンの文字中央にマウスを置き、F9。マウス周囲240×40ピクセルを登録します。レポートフォルダを開くボタンと間違えないでください。
5. サーバー一覧で接続対象の行を選択し、サーバー名の文字中央にマウスを置き、F10。アドレス・名前は正しい接続先であることを確認してください。人数・説明文・pingなど変化する部分をできるだけ含めないでください。登録画像の中央をダブルクリックして接続します。
6. 一度手動接続し、Minecraftを前面にしてF6で監視開始。

画像は `%AppData%\PatrolReconnectV4` に保存されます。誤クリック防止のため、保存したback.bmp/server.bmpを確認してください。解像度・GUIスケール・言語を変更したら画像を再登録します。最小化や背面での自動操作はしません。初回は必ず付き添いで試してください。

## 操作と制限

- F6: 監視開始・回数リセット（すでにあるログとレポートは無視）
- F7: 監視と予約操作をすべて停止。手動切断・サーバー停止の前にも必ず押す
- F8: 終了
- F5/F9/F10: 設定変更。監視は停止するので設定後はF6

Connection resetなどの新しいログ、またはゲームフォルダ内 `debug/disconnect-*-client.txt` の新規・更新レポートを検出します。単なるDisconnectedは手動切断と区別できないので対象外。重複ログイン・キック等の文言を検出した場合は停止します。ただし、理由がConnection resetのみなら手動停止との完全な区別はできません。

検出10秒後、対象ウィンドウと戻るボタン画像を確認してクリック。4秒後に登録サーバー名を確認してダブルクリックします。監視開始1回につき最大3回の接続操作です。1回の障害に対し、状態不明のまま連打しません。30秒後も登録メニュー画像が見えれば停止し、そうでなければキーを送らず監視に戻ります。これは接続成功の証明ではなく、成功したとの表示もしません。接続失敗・画面変化・フォーカス移動時は手動確認が必要です。Falixが停止していたら管理画面から起動してください。

Windows通知と `%AppData%\PatrolReconnectV4\reconnect.log` に動作理由を記録。機密を含むMinecraftログ全体は複製しません。

## 検証

`AutoHotkey64.exe /ErrorStdOut anti_afk_simple_v4.ahk --self-test` は11件の判定テストのみを実行し、画面・キー操作・設定ファイル作成を行いません。実Minecraftでの画像認識・再接続は配信用PCでの確認が必要です。
